# interviewer-copilot — AI Interview Copilot (Windows)

Tauri 2 (Rust) + React/TypeScript/Vite/Tailwind v4/shadcn desktop app. It captures the interviewer's voice from the Windows audio **output** (WASAPI loopback, never a microphone), transcribes it locally (faster-whisper, English) and streams structured answer suggestions from Claude. Owner: Marcos (GitHub `H0wZy`). Repo: `https://github.com/H0wZy/interviewer-copilot` (**public**).

## Non-negotiable rules
1. **Loopback only.** Audio comes exclusively from a render (output) endpoint via WASAPI loopback (`AUDCLNT_STREAMFLAGS_LOOPBACK`). Never open a capture endpoint: not the microphone, not "Stereo Mix", not any default-capture device. The only allowed contact with capture endpoints: listing them by name in `tools/diagnostics`, and the H4 hardware test (`GetDevice` + `GetDataFlow` on a synthetic capture id, never `Activate`). Process loopback (SPEC S8) is a tap on render audio that uses no endpoint; it needs its own decision-log entry and Marcos's approval before it is built.
2. **No fallback.** If loopback fails or the output device is unavailable, surface an explicit typed error in the UI. Never switch to an input device and never change the user's selected target on your own. `FollowDefault` re-resolving to Windows' new default output is allowed because the user chose it and the UI shows every switch (ARCHITECTURE 3.2); a `Pinned` device never moves.
3. **Phase gates.** Phase 2 (shell + loopback engine + device selector + level meter) must be proven with real desktop audio before any Whisper (Phase 3) or Anthropic (Phase 4) code. Every phase ends with a verification gate (SPEC section 7) and Marcos's written confirmation.
4. **Ask before acting on the machine.** No installs (UAC prompts, licenses, multi-GB downloads), no Smart App Control or Defender changes, no system settings changes without Marcos's explicit authorization for that machine. Until Marcos has answered SPEC P-1 (approve ARCHITECTURE v2) and P-2 (authorize installs): no application code, no scaffolding, no installs; Phase 0 is read-only.

## How to work (spec-driven + workflows)
- **Spec first:** every change starts from a SPEC task. If the spec or the architecture turns out wrong, update it (and the SPEC decision log) with the code, never silently. Keep the SPEC status table, the 'very next actions' list and the checkboxes current, and mirror any phase or decision change into the other status copies: README.md (pt-BR Status table), docs/README.md (notes column), the ARCHITECTURE.md status line and docs/findings/README.md rows.
- **Teammates:** orchestrate development with the Workflow tool (if this install has no Workflow tool, do the same steps serially yourself with the same effort rules); every teammate is **Sonnet 5.5** (`model: 'sonnet'`) with effort `high` for routine work and `max` for complex or critical work (audio engine, Timeline, no-mic guarantee, adversarial verification, final reviews). The main session plans, reviews and integrates. Parallelize only file-disjoint authoring; run cargo commands one at a time.
- **Definition of done:** the task's done-criteria plus `cargo fmt --check`, `cargo clippy`, `cargo test` (and the relevant `-- --ignored` hardware tests), `tsc --noEmit`, `npm run build`, `npm run check:nomic`, wherever they exist. Report failures with their output; never claim a check you did not run.
- **Before any Phase 4 (Anthropic) code:** load the `claude-api` skill and re-verify model ids, prices and API rules. The brief's `claude-3-5-sonnet` is retired.

## Conventions
- STT input format: PCM 16 kHz, 16-bit, mono. Interviews are English only (`.en` Whisper models).
- Identifier prefix `ic-` (threads `ic-wasapi`, `ic-dsp`, ...; log target `ic::audio`; files `ic-<unix_ms>.wav`). App identifier `com.interviewercopilot.app`.
- Secrets: the Anthropic API key is stored only in Windows Credential Manager. Marcos types it once into a password field of the app (it crosses the webview only at that moment, is cleared from UI state at once and is never returned or shown again); it never goes into source, plain files (not even `.env`), logs or chat. Dev-only exception: Marcos may export `ANTHROPIC_API_KEY` in his own terminal session for debug builds and the L-1 smoke test; the agent never asks for it, reads it from a file, writes it or prints it. `.env` is gitignored and must not hold the key.
- The repo is public: never commit personal data (CV, `systeminfo.md`, e-mails, IPs, product IDs, Windows user names), WAV recordings, models, venvs or build outputs.
- Git: commit and push only when Marcos asks; one branch per phase step (e.g. `phase-0/h0wzy-pc-report`, `phase-2/s1-scaffold`), merged into `main` only when Marcos says so; commit messages end with the co-author line the environment provides.

## Commands
- Audio diagnostics (read-only; run from the repo root; play audio while it runs; forward slashes so it also works in Git Bash): `powershell -ExecutionPolicy Bypass -File tools/diagnostics/audio-probe.ps1 -Seconds 3`
- From S1 on (see SPEC 6.2): `npm run tauri dev`, `npm run build`, `npm run check:nomic`; in `src-tauri/`: `cargo check`, `cargo test --lib`, `cargo test -- --ignored` (hardware tests), `cargo clippy`, `cargo fmt --check`.
